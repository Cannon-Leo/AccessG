# AccessG: Ship & Found Architecture

AccessG is a dual-engine event ticketing platform: fast-checkout general admission for public events, and AccessG Studio for creator micro-events under 20 attendees.

## Repository Status
- **Status:** Task 1 (Design System) in progress. Tasks 2–5 initialized.
- **Architecture:** Monorepo organized strictly across the 5 assessment milestones.

## Directory Structure
- `task-01-design-system/`: Design system tokens, Figma variables, typography, shadows, contrast checks, and token consumption proofs.
  - `docs/`: Written deliverables (`business-brief.md`, `type-scale.md`, `colour-roles.md`, `shadows.md`, `divergences.md`, `prompts.md`, `defects.md`, `interview-answers.md`).
  - `evidence/`: Screenshots, JSON token exports, and terminal text outputs.
- `task-02-repository-and-scaffold/`: Initial project scaffold, dev server logs, runtime database diagnostics, hand-drawn git tree.
- `task-03-client-validation/`: Single-page auth transition, client-side validation rules, accessibility audit & screen-reader proofs, direct endpoint bypass.
- `task-04-server-security/`: Database schema, migrations, Argon2id/bcrypt hashing benchmarks, Zod boundary validation, rate limiting, and verification jobs.
- `task-05-sessions-compliance-defence/`: Session lifecycle, role-based route security, soft/hard gating, lawful deletion & data retention matrix, owner interview, and comprehensive engineering handbook.
